# iOS 负片预览设计方案

状态：已实现并完成模拟器关键流程验证；未发布，2026-09-27。建议分支：`codex/ios-negative-film-preview`。
本轮按用户要求收敛为负片 preview：照片输入必须支持大文件 TIFF，输出支持 TIFF、PNG、JPG；不增加其他功能。实际实现与验证记录见文末；尚未完成真机验证。

## 1. 功能范围

上线平台限定为 iOS 端的 **iPhone 和 iPad（iPadOS）**，两者均为正式支持设备，随现有应用发布。macOS 不新增该功能。沿用项目现有最低系统版本，不因本功能擅自提高部署要求。此处定义发布目标；未提交 App Store。

核心流程只有：**输入负片 → 选取片基 → 查看正片 → 按需导出**。

- 保留已规划的相机实时预览与单张照片输入。
- 照片输入：TIFF（`.tif` / `.tiff`，包含大文件）、JPEG、PNG、HEIF；提供“照片”和“文件”两个系统选择入口，TIFF 以文件导入为主要路径。
- 片基取色、确认、取消和重选；原片/正片切换，缩放和平移用于观察及定位片边。
- 相机仅保留必要的对焦、曝光/白平衡锁定、定格/继续。
- 输出当前正片为 TIFF、PNG 或 JPG，保存副本，不覆盖输入；也可将 JPG 正片直接保存到系统相册。

**不做**亮度、对比度、色温、色调、曲线等编辑功能，也不增加胶片模式选择、裁切旋转、批量处理、预设、历史记录、项目保存、胶片型号校准、除尘或同步。此列表是当前范围边界，不是后续开发承诺。

胶片为黑白时同样走片基校正和反转，不增加单独去色模式。未选片基时显示原片并引导取色，不额外提供“仅反转”模式。

实施前基线：iOS 只有计算、快门、设置；macOS 胶片模块目前仅做导入、切片和导出。新功能独立加入 iOS，不恢复历史调色逻辑，不改变 macOS 或 `.fffilm` 项目的现有语义。参见 `film-color-management.md`。

## 2. 使用流程

### 照片与文件

1. 进入“负片”页面，选择“导入照片”或“导入文件”。
2. 异步读取文件信息和方向，生成适配屏幕的预览。大 TIFF 展示读取状态并允许取消，界面保持可操作。
3. 点击“选取片基”，在原片未曝光的片边或帧间区域定位取色框，避开齿孔、文字和画面。
4. 显示局部放大区域与候选色块，点击“使用此片基”后查看正片。取消取色保留之前的有效结果。
5. 切换原片/正片、缩放检查；需要时重新取色。
6. 点击“导出正片”，只选择 TIFF、PNG、JPG 格式，生成后交给系统分享面板保存到文件或其他目标。

新图像不继承上一张图像的片基。取消导入或读取失败保留上一成功图像。没有未曝光片边时提示需要包含片边的照片，不把最亮区域猜测为片基。

### 相机

1. 用户点击“打开相机”后才请求权限；默认后置主摄；可手动选择设备实际提供的后置主摄、超广角或长焦，不使用自动切换的虚拟多摄，不开闪光灯。
2. 将负片置于均匀背光上，画面保留一段片边。默认点按对焦，可恢复连续自动对焦；选择“取片基”点按模式后，点按才进入取样。显示镜头报告的最近对焦距离；固定对焦镜头明确提示移动手机与胶片的距离。
3. 点击“选取片基”后等待曝光与白平衡稳定，锁定实际配置，并冻结锁定完成后的新帧供取色。
4. 确认片基后恢复实时正片；显示“曝光与白平衡已锁定”。
5. 定格查看或导出；导出使用当前冻结源帧与片基，不另拍一张曝光不同的照片。

锁定失败时不能显示已锁定；可对冻结帧进行静态预览，或使用文件输入。镜头/曝光/白平衡/采集格式变化或相机中断恢复后，要求重新取片基。数字缩放与显示方向变化不应误清片基。

## 3. 最小界面

沿用 `DESIGN.md` 的单色表面、原生控件和 44pt 触摸目标。新增“负片”标签页，位于快门与设置之间。图像及片基色块保留真实颜色。

```text
负片                        [输入]
                      [原片 / 正片]
┌──────────────────────────────────┐
│                                  │
│             图像预览              │
│                                  │
└──────────────────────────────────┘
片基 [色块]                [选取 / 重选]
[定格 / 继续，仅相机]          [导出正片]
```

- 完整适配图像，不裁掉片边；预览缩放和平移不改变导出范围。
- 取色模式提供确认和取消，只有确认才生效。默认持续自动对焦，普通点按只调整持续对焦区域；仅“选取片基”按钮触发取色锁定。
- 未取色时禁用正片展示与导出，并给出“先选取未曝光片基”的原因。
- 相机设置使用原生折叠区域，提供镜头、采集分辨率（设备支持的 720p/1080p/4K）、持续自动对焦状态。不提供手动曝光补偿：亮度由连续自动曝光与片基采样归一化处理。设置变化清除片基并重新启动采集；取样、忙碌和暂停时禁用。照片/文件输入不显示相机控件。
- 默认保持 720p；4K 的显示处理最多 15fps，普通分辨率最多 30fps，严重热状态最多 10fps。原片/正片采用选定的采集尺寸，界面报告实际帧尺寸；不保证所有设备支持所有分辨率。
- 中英文进入现有 String Catalog。VoiceOver 能读取按钮、取色状态和错误；取色框提供方向移动操作，不只支持拖动。
- 大字体时控件可滚动且不遮挡确认按钮。错误和进度使用稳定区域，不能只用颜色表达状态。

## 4. 大文件 TIFF 输入契约

“大文件支持”须以原始像素数、位深、解码峰值内存和真机结果定义，不能仅看压缩后的文件体积，也不承诺无限大小。

- 首版支持经验证可解码的单图像 8/16-bit RGB 和灰度 TIFF，读取嵌入 ICC 与方向。对多页 TIFF、不支持的像素类型/压缩方式或损坏文件给出明确提示，不静默取第一页当完整输入。
- 先读取元数据，再按目标显示尺寸生成降采样预览；保留源文件 URL，不把整文件读成 `Data` 后再创建多个全尺寸位图。
- 文件选择器权限和来源生命周期正确管理；外部文件需要时复制到受控临时目录，允许等待文件提供器下载、取消和失败重试。所需临时空间不足时提前提示。
- UI 预览降采样属于显示优化，不能把预览位图误当原始导出数据。片基区域映射到原图，在源精度下采样，不从已量化屏幕截图取色。
- 解码/取样/导出任务串行限制峰值内存，取消或换图后释放缓存；旧任务结果不能覆盖新输入。
- 实施时必须测量解码器实际行为：创建缩略图或裁切请求不等于底层一定按区域解码。若系统路径超出内存预算，应采用经验证的分块/磁盘暂存路径；是否需要额外解码依赖以实测为据。
- 资源不足时返回可恢复错误，保留当前预览，不崩溃、不静默缩小导出尺寸。正常大文件样本必须成功导入并完成三种格式导出，不能以“资源不足提示”替代大文件支持。
- 验收样本至少含约 85MP 的 16-bit RGB TIFF（例如 5167×16443，未压缩 RGB 约 486MiB），覆盖压缩与未压缩版本；另用更大样本验证资源边界。此为待验证目标，实际支持边界根据最低支持真机测试记录。

## 5. 片基与转换

取样来自未经反转的源图像。归一化取色坐标统一处理方向、显示缩放和平移；图像外的留黑区域不能被取样。

取样使用小区域统计而非单像素；排除透明/非法像素，用截尾均值降低灰尘噪点影响。区域越界、有效像素不足、通道过暗或剪切时禁止确认并说明如何重选；不均匀区域提示用户检查。阈值按源位深与工作空间定义，用真实样本验证，不能直接把 8-bit 阈值套到浮点值上。

基线管线：

1. 根据输入 ICC 或相机色彩附件转换到明确的线性工作 RGB；灰度输入正确转换为 RGB。未标记照片按 sRGB 解释并提示该假设，未标记 TIFF 同样不能冒充已知扫描器色彩配置。
2. 在同一线性域逐通道计算 `N = C / max(B, ε)`，C 为负片像素、B 为片基。以线性 sRGB 为首版工作域。
3. 显示编码域反转为 `P = 1 - sRGBEncode(clamp(N, 0, 1))`，明确编码状态，输出时不得重复编码。内部计算保持浮点精度，输出前才按目标位深量化。
4. 同一算法用于缩略预览、相机帧和源尺寸导出，不加自动黑白场、动态直方图拉伸或额外调色。首版输出 SDR sRGB；HDR 输入需显式映射为 SDR，不能无说明地直接夹断。

片基绑定来源 ID、颜色空间与算法版本；相机还绑定采集配置版本。C=B 应接近黑色，较暗负片应映射为较亮正片，非法值不产生 NaN/Inf。同一输入重复处理结果稳定。

该算法是预览用途的设计基线，须以真实负片评估。它减少片基底色影响，不承诺校准级还原，也不因结果偏色而擅自扩展调色工具。

## 6. 输出契约

| 格式 | 固定输出规格 | 用途 |
| --- | --- | --- |
| TIFF（`.tiff`） | 16-bit/channel RGB，嵌入 sRGB ICC，无损编码 | 保留转换结果的数值精度 |
| PNG（`.png`） | 16-bit/channel RGB，嵌入 sRGB ICC，无损编码 | 无损预览副本 |
| JPG（`.jpg`） | 8-bit/channel RGB，嵌入 sRGB ICC，固定高质量编码 | 常用分享副本 |

这些是固定实现规格，不增加位深、压缩、色彩空间等高级设置。低位深输入输出到 16-bit 不会恢复原本不存在的细节。

- 导入图像按方向校正后的原始像素尺寸导出；大 TIFF 也适用。相机按冻结帧实际尺寸导出并显示尺寸，不称为高分辨率拍照。
- 正片预览与导出共用片基和算法。导出无界面、选框或预览缩放裁切；透明区域统一合成到白色，三种格式保持一致外观。
- 输出格式选择只影响文件编码，不改变反转结果。原片对照期间按钮仍叫“导出正片”。
- 提供导出中、取消和失败状态，禁止重复启动大文件导出；失败不丢失输入与片基。
- 先写临时文件，编码成功后再交给系统分享面板或 PhotoKit（保存到相册固定使用 JPG）；避免覆盖源文件，清理取消/失败的半成品。临时文件在分享读取或相册写入结束后再清理。
- 不静默降采样。超过可处理边界时说明原因；实际支持边界必须靠大文件导入到导出的完整真机测试确认。

## 7. 生命周期与隐私

- 离开负片页、进入后台或发生相机中断时停止采集，旧帧标记为已暂停；恢复后重取片基。
- 新图像载入成功后才替换旧来源；取色取消保留旧样本，但已经改变采集配置的样本不能恢复有效状态。
- 只保留当前会话，不增加持久化历史或预设。现有计算、快门和 macOS 行为保持不变。
- 处理在本机完成，不上传图像。照片选择器仅访问选中内容，文件入口仅访问用户所选文件；相机不请求麦克风权限。
- 输出去除原图定位元数据；不申请整库权限，导出由系统分享面板完成。

## 8. 实施与验收

实施顺序：先打通大 TIFF 文件输入、片基采样、预览与三格式导出，再接入相机帧和锁定，最后完成真机与现有功能回归。不以新增编辑能力扩大任务范围。

技术边界：复用 Core Image/Metal context，重任务离开主线程，采集与大图处理使用有界队列；以来源/采集版本丢弃迟到结果。图像数学独立于 UI，便于测试；代码注明颜色域、坐标映射及解码内存约束。

必须验证：

- 8/16-bit RGB、灰度 TIFF、压缩/未压缩大 TIFF；PNG/JPEG/HEIF 常规输入，以及损坏和不支持类型的可恢复错误。
- 约 85MP 16-bit RGB TIFF 在最低支持真机成功预览、源精度取样及原尺寸三格式导出，记录峰值内存、耗时和临时磁盘占用；更大样本验证边界。
- TIFF/PNG/JPG 输出重新读取，核对像素尺寸、位深、颜色配置、文件格式和方向；比较统一尺寸下的预览与导出，JPG 允许编码误差。
- 合成片基、灰阶、噪声、透明边、近零值和剪切样本；验证映射单调、结果有限及取样坐标准确。
- sRGB/P3/灰度配置输入、无 ICC 提示、EXIF 各方向和缩放平移后的取色定位。
- 取消导入、取消导出、磁盘不足、文件提供器下载失败、换图及迟到任务不会损坏当前会话。
- 真机权限拒绝、相机锁定失败、中断恢复和同一冻结帧导出；模拟器不能替代相机或大文件内存验收。
- iPhone 和 iPad 都必须通过导入、片基取色、正片预览及 TIFF/PNG/JPG 导出的完整流程；两类真机分别验证大 TIFF 内存行为与相机流程。
- iPhone 覆盖紧凑屏幕、横竖屏与安全区；iPad 覆盖全屏、横竖屏、分屏和可调整大小窗口，窗口变化保持当前图像与片基。
- 两个平台均检查中英文、大字体和 VoiceOver 基础操作；现有 iOS/macOS build 与相关回归通过。
- 发布前核对 iPhone/iPad 设备支持、相机用途说明和文件类型声明；实现、真机验证与发布准备完成后，再按用户授权执行实际发布。

## 9. 实施记录

- iOS 新增 `NegativePreviewView` 与 `NegativeStore`，只包含输入、取色、对照、观察和导出；支持照片选择器和文件选择器，不改变计算或快门状态。
- `NegativeRenderer` 负责源文件副本、ICC/方向、源精度区域取样和编码域反转；ImageIO 显式请求 SDR 解码，兼容普通 HEIF/JPEG 的 SDR 路径。未标记 RGB 假设 sRGB，未标记灰度使用解码器默认灰度空间并提示缺少配置。
- `NegativeFilePixels` 在向 Core Image 提交前裁切源区域，避免把整张扫描图上传为 GPU 纹理；预览使用有界浮点位图。`NegativeRaster` 按 256 行渲染，使用预分配的磁盘映射缓冲交给 ImageIO 编码，保留原尺寸。保留一份完整 CPU 解码缓冲，避免 LZW/PackBits 每区域重复解压；真机在解码和导出前检查当前进程剩余内存预算，不宣称恒定内存或无限大文件支持。
- 相机服务默认主摄并支持手动镜头/分辨率/曝光补偿、锁定曝光/白平衡、等待锁定帧、支持定格与中断恢复；一次只向主线程交付一帧。过热时降帧率或暂停。系统授权弹窗使场景暂时 inactive 时不取消授权流程，进入后台/离开标签页时停止采集。
- 中英文相机用途说明加入 InfoPlist 字符串目录，macOS 排除该目录；权限仅在用户打开相机时申请，无麦克风/照片整库权限。
- 源文件和分享副本拥有独立生命周期；失败或取消任务不发布迟到结果，正常释放后清理临时文件。异常退出后的临时文件由系统临时目录管理。

### 持续对焦与自动微距（2026-09-28）

- 实时相机始终优先 continuousAutoFocus，点按仅调整对焦区域；移除单独的恢复自动对焦按钮。
